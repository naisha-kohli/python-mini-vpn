## 3. Create Two Network Namespaces

```bash
sudo ip netns add vpnA
```

Created the first isolated network namespace, representing Computer A.

```bash
sudo ip netns add vpnB
```

Created the second isolated network namespace, representing Computer B.

```bash
sudo ip netns list
```

Verified that both namespaces were created.

### Theory

A **network namespace** provides an isolated networking environment with its own interfaces, IP addresses, routes, and networking state.

This allows two separate networking environments to be simulated inside one Kali installation instead of using two physical computers.

---

## 4. Connect the Namespaces

### Create a virtual Ethernet cable

```bash
sudo ip link add vethA type veth peer name vethB
```

Created a **veth pair**, which acts like a virtual Ethernet cable.

### Move each end into a namespace

```bash
sudo ip link set vethA netns vpnA
```

Moved `vethA` into `vpnA`.

```bash
sudo ip link set vethB netns vpnB
```

Moved `vethB` into `vpnB`.

The setup is now:

```text
vpnA                         vpnB
vethA ====================== vethB
        Virtual Ethernet
```

---

## 5. Assign IP Addresses

```bash
sudo ip netns exec vpnA ip addr add 10.10.0.1/24 dev vethA
```

Assigned `10.10.0.1` to `vethA` inside `vpnA`.

```bash
sudo ip netns exec vpnB ip addr add 10.10.0.2/24 dev vethB
```

Assigned `10.10.0.2` to `vethB` inside `vpnB`.

The two namespaces are now on the same virtual network:

```text
vpnA: 10.10.0.1
   |
   | veth pair
   |
vpnB: 10.10.0.2
```

## 7. Test Connectivity

If replies are received, the virtual network is working correctly.

# Theory Checkpoint #1

### 1. What is an interface?

A **network interface** is a connection point through which a system sends and receives network traffic. It can be physical, such as Wi-Fi, or virtual, such as a veth interface.

### 2. What is an IP address?

An **IP address** identifies a network interface on a network so that packets can be sent to it.

Example:

```text
10.10.0.1
```

### 3. What is a route?

A **route** tells the operating system where and through which interface to send packets based on their destination IP address.

### 4. What is a network namespace?

A **network namespace** is an isolated Linux networking environment with its own interfaces, IP addresses, routing table, and network state.

### 5. What is a veth pair?

A **veth pair** consists of two virtual Ethernet interfaces connected to each other. Traffic entering one end appears at the other end.

### 6. Why use two namespaces instead of two physical computers?

Two namespaces allow me to simulate two separate computers **inside one Kali installation**. This provides isolated networking environments for experimentation without interfering with my normal network.

# 8.6 Network Architecture

At this point, two separate networks exist:

### Underlying / Transport Network

```text
vpnA                         vpnB
10.10.0.1                   10.10.0.2
   │                            │
 vethA ═══════════════════════ vethB
          Virtual Ethernet
```

This is the network through which the VPN endpoints will communicate.

### Virtual VPN Network

```text
vpnA                         vpnB
10.20.0.1                   10.20.0.2
   │                            │
 tun0                         tun0
```

This is the virtual network that the VPN tunnel will provide.

# Part 10 — Create a Reusable Lab Setup Script

Because the network namespaces, veth interfaces, IP addresses, and TUN interfaces are temporary and need to be recreated after restarting Kali, I created a script to automate the setup.

```bash
nano setup_lab.sh
```

Created a shell script for rebuilding the VPN networking environment.

The script contains the commands required to:

- Create `vpnA` and `vpnB`
- Create the `vethA ↔ vethB` virtual Ethernet connection
- Assign `10.10.0.1/24` and `10.10.0.2/24`
- Bring the veth interfaces up
- Create `tun0` inside both namespaces
- Assign `10.20.0.1/24` and `10.20.0.2/24`
- Bring the TUN interfaces up
- Display the final configuration

### Make the script executable

```bash
chmod +x setup_lab.sh
```

Made the setup script executable.

### Run the setup script

```bash
./setup_lab.sh
```

Running this script recreates the networking lab instead of manually entering every networking command again.
