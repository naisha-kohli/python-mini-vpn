# Mini VPN Project — Network Lab Setup & Python Environment

## Project Overview

This project creates a small VPN lab inside Kali Linux using:

* Linux Network Namespaces
* Virtual Ethernet (`veth`) pairs
* TUN interfaces
* UDP communication
* Python
* Cryptography
* `tcpdump`
* Wireshark

The purpose is to simulate two separate computers inside one Kali Linux system and later use them to build and test a VPN.

## Theory — Network Namespace

A **network namespace** provides an isolated networking environment with its own:

* Network interfaces
* IP addresses
* Routing table
* Network state

This allows two separate networking environments to be simulated inside one Kali installation instead of using two physical computers.

# Part 5 — Connect the Two Namespaces

The two namespaces need a virtual connection between them.

## 5.1 Create a Virtual Ethernet Pair

```bash
sudo ip link add vethA type veth peer name vethB
```

**Description:** Created a veth pair that behaves like a virtual Ethernet cable between the two namespaces.

---

## 5.2 Move `vethA` into `vpnA`

```bash
sudo ip link set vethA netns vpnA
```

**Description:** Moved one end of the virtual Ethernet connection into `vpnA`.

---

## 5.3 Move `vethB` into `vpnB`

```bash
sudo ip link set vethB netns vpnB
```

**Description:** Moved the other end of the virtual Ethernet connection into `vpnB`.

---

## Network Layout

```text
vpnA                         vpnB
vethA ====================== vethB
         Virtual Ethernet
```

The veth pair acts like a virtual network cable connecting the two simulated computers.

---

# Part 6 — Configure the Transport Network

The veth interfaces are given IP addresses so that `vpnA` and `vpnB` can communicate.

## 6.1 Assign IP Address to `vpnA`

```bash
sudo ip netns exec vpnA ip addr add 10.10.0.1/24 dev vethA
```

**Description:** Assigned `10.10.0.1/24` to `vethA` inside `vpnA`.

---

## 6.2 Assign IP Address to `vpnB`

```bash
sudo ip netns exec vpnB ip addr add 10.10.0.2/24 dev vethB
```

**Description:** Assigned `10.10.0.2/24` to `vethB` inside `vpnB`.

---

## Transport Network

```text
vpnA: 10.10.0.1
      |
      | veth pair
      |
vpnB: 10.10.0.2
```

The `10.10.0.0/24` network is the **underlying transport network** that will later carry the VPN's UDP traffic.

# Part 13 — Understand the Network Architecture

At this point, two separate networks exist.

## 13.1 Underlying / Transport Network

```text
vpnA                         vpnB
10.10.0.1                   10.10.0.2
   │                            │
 vethA ═══════════════════════ vethB
          Virtual Ethernet
```

**Purpose:** This network provides the underlying connection between the two VPN endpoints and will carry the VPN's UDP traffic.

---

## 13.2 Virtual VPN Network

```text
vpnA                         vpnB
10.20.0.1                   10.20.0.2
   │                            │
 tun0                         tun0
```

**Purpose:** This is the virtual network that the VPN tunnel will provide.

---

## Important Concept

The two networks have different purposes:

```text
10.10.0.0/24
     ↓
Underlying transport network
     ↓
Carries VPN traffic


10.20.0.0/24
     ↓
Virtual VPN network
     ↓
Carries traffic through the TUN tunnel
```

# Part 18 — Complete `setup_lab.sh`

The following script is reconstructed from the networking commands documented during the lab.

```bash
#!/bin/bash

# Create network namespaces
sudo ip netns add vpnA
sudo ip netns add vpnB

# Create virtual Ethernet pair
sudo ip link add vethA type veth peer name vethB

# Move each veth interface into its namespace
sudo ip link set vethA netns vpnA
sudo ip link set vethB netns vpnB

# Assign transport-network IP addresses
sudo ip netns exec vpnA ip addr add 10.10.0.1/24 dev vethA
sudo ip netns exec vpnB ip addr add 10.10.0.2/24 dev vethB

# Bring loopback interfaces up
sudo ip netns exec vpnA ip link set lo up
sudo ip netns exec vpnB ip link set lo up

# Bring veth interfaces up
sudo ip netns exec vpnA ip link set vethA up
sudo ip netns exec vpnB ip link set vethB up

# Create TUN interface in vpnA
sudo ip netns exec vpnA ip tuntap add dev tun0 mode tun
sudo ip netns exec vpnA ip addr add 10.20.0.1/24 dev tun0
sudo ip netns exec vpnA ip link set tun0 up

# Create TUN interface in vpnB
sudo ip netns exec vpnB ip tuntap add dev tun0 mode tun
sudo ip netns exec vpnB ip addr add 10.20.0.2/24 dev tun0
sudo ip netns exec vpnB ip link set tun0 up

# Display final configuration
echo "===== vpnA ====="
sudo ip netns exec vpnA ip addr

echo "===== vpnB ====="
sudo ip netns exec vpnB ip addr
```

**Description:** This script automates the creation of the complete networking lab, including the two namespaces, veth connection, transport-network IP addresses, TUN interfaces, VPN-network IP addresses, and final configuration display.

> **Important:** The attached notes document what the script was intended to contain, but they do not include the original contents of `setup_lab.sh`. Therefore, the code above is a reconstruction from the commands recorded in the notes, not a verbatim copy of the original terminal script.

After completing these steps, the lab looks like this:

```text
                    UNDERLYING NETWORK
                    10.10.0.0/24

              vethA                 vethB
                │                     │
        ┌───────┴───────┐     ┌──────┴────────┐
        │     vpnA      │     │      vpnB     │
        │ 10.10.0.1     │     │  10.10.0.2    │
        │               │     │                │
        │     tun0      │     │      tun0      │
        │  10.20.0.1    │     │   10.20.0.2    │
        └───────────────┘     └────────────────┘

                    VIRTUAL VPN NETWORK
                    10.20.0.0/24
```

At this stage, the networking laboratory and TUN interfaces have been prepared. The actual Python VPN program still needs to open the TUN devices and transport packets between the two endpoints.
