# Mini VPN Project - Network Lab and TUN-over-UDP Tunnel

## Project overview

This is a beginner-friendly Mini VPN project built and tested locally on Kali Linux.

The project uses:

- Linux network namespaces
- Virtual Ethernet (`veth`) pairs
- TUN interfaces
- UDP sockets
- Python
- `tcpdump` and Wireshark
- The `cryptography` Python library for a future encryption stage

The goal is to understand the path a VPN packet follows:

```text
Application
    ↓
Linux network stack
    ↓
TUN interface
    ↓
Python VPN program
    ↓
UDP transport network
    ↓
Python VPN program on the peer
    ↓
Peer TUN interface
    ↓
Peer Linux network stack
```

This lab runs entirely on my own Kali machine. The two network namespaces simulate two separate computers.

# Part 4 - Manual lab design

The lab contains two isolated network namespaces:

```text
vpnA = simulated computer A
vpnB = simulated computer B
```

A namespace has its own interfaces, IP addresses, routes, and network state. This lets me create two virtual machines without needing a second physical computer.

The namespaces are connected with a veth pair:

```text
vpnA                                  vpnB
vethA =============================== vethB
          virtual Ethernet cable
```

The veth pair is the underlying transport connection for the VPN's UDP packets.

---

# Part 5 - Network addressing

## Underlying transport network

```text
vpnA / vethA: 10.10.0.1/24
vpnB / vethB: 10.10.0.2/24
```

This network carries the outer UDP packets between VPN-A and VPN-B.

Test it with:

```bash
sudo ip netns exec vpnA ping -c 3 10.10.0.2
```

A successful ping proves that the base virtual network is working.

## Virtual VPN network

```text
vpnA / tun0: 10.20.0.1/24
vpnB / tun0: 10.20.0.2/24
```

This is the inner virtual network carried through the VPN tunnel.

# Part 8 - Python VPN peers

The project uses two Python programs:

```text
vpn.py   = VPN peer A, running inside vpnA
vpnB.py  = VPN peer B, running inside vpnB
```

Each program:

1. Opens `tun0`.
2. Reads IP packets sent by Linux to `tun0`.
3. Sends those packets through a UDP socket over `10.10.0.0/24`.
4. Receives UDP packets from the other peer.
5. Writes the original IP packets into its local `tun0`.

The Python peers must both use:

```python
b"tun0",
```

This is important because the VPN test addresses `10.20.0.1` and `10.20.0.2` are configured on `tun0`, not `tun1`.

# Part 9 - Start the Mini VPN

Open two separate terminals.

## Terminal 1 - Start VPN-A

```bash
cd ~/mini-vpn
sudo ip netns exec vpnA python3 vpn.py
```

Runs the VPN-A Python program inside the `vpnA` namespace.

## Terminal 2 - Start VPN-B

```bash
cd ~/mini-vpn
sudo ip netns exec vpnB python3 vpnB.py
```

Runs the VPN-B Python program inside the `vpnB` namespace.

Both terminals must stay open while testing the tunnel.

---

# Part 10 - Test the VPN tunnel

Open a third terminal:

```bash
sudo ip netns exec vpnA ping -c 3 10.20.0.2
```

Successful output:

```text
64 bytes from 10.20.0.2 ...
3 packets transmitted, 3 received, 0% packet loss
```

This proves that traffic travelled through the full tunnel:

```text
vpnA tun0 (10.20.0.1)
    ↓
VPN-A Python program
    ↓
UDP over 10.10.0.1 → 10.10.0.2
    ↓
VPN-B Python program
    ↓
vpnB tun0 (10.20.0.2)
```

# Part 11 - Useful troubleshooting commands

## Verify the base transport network

```bash
sudo ip netns exec vpnA ping -c 3 10.10.0.2
```

Tests the veth connection. This must work before testing the VPN tunnel.

## Check the route for VPN traffic

```bash
sudo ip netns exec vpnA ip route get 10.20.0.2
```

Expected result:

```text
10.20.0.2 dev tun0 src 10.20.0.1
```

This confirms Linux sends VPN traffic into `tun0`.

## Check whether VPN programs are running

```bash
sudo ip netns pids vpnA
sudo ip netns pids vpnB
```

Shows process IDs currently running inside each namespace.

## Check UDP sockets

```bash
sudo ip netns exec vpnA ss -lunp
sudo ip netns exec vpnB ss -lunp
```

Shows UDP sockets opened by the Python VPN programs.

## Capture tunnel packets

```bash
sudo ip netns exec vpnA tcpdump -ni vethA udp port 5555 -X
```

Captures the outer UDP packets crossing the transport network. This is useful for comparing unencrypted traffic with encrypted traffic later.

The unencrypted TUN-over-UDP Mini VPN is working successfully.

```text
vpnA can ping vpnB through 10.20.0.1 → 10.20.0.2
```

The next stages are:

3. Add X25519 key exchange.
4. Derive a session key rather than using a hardcoded key.
5. Add routing for a small private test network.
6. Learn forwarding, NAT, MTU handling, replay protection, and rekeying.
